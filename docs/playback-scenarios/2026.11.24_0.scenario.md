## 4. Bit-Level Root Cause Analysis

### 4.1 Exact Bit Flips Inside `00 00 01 B5 1x` (`Sequence Extension`)
Per ISO/IEC 13818-2 §6.2.2.3, the 10-byte `sequence_extension()` (`00 00 01 B5 1x`) packs all four VAAPI-critical decoder parameters into **two adjacent bytes** (`offset + 5` and `offset + 6`):
- `byte 5, bit 3` (`0x08`): `progressive_sequence` — flipping `0 → 1` on `1080i` triggered `interlaced frame in progressive sequence, ignoring` and `MT_DMV in progressive_sequence`.
- `byte 5, bits 2..1` (`0x06`): `chroma_format` — ATSC 1.0 mandates `01` (`4:2:0`, `yuv420p` → VAAPI `NV12`); flipping to `10` (`4:2:2`) or `11` (`4:4:4`) changes `AVFrame.format` to a format unsupported by Intel HD 530 `hwupload`.
- `byte 5, bit 0` (`0x01`) + `byte 6, bit 7` (`0x80`): `horizontal_size_extension` — adds `+4096..+12288 px` to width.
- `byte 6, bits 6..5` (`0x60`): `vertical_size_extension` — flipping `00 → 01` inflated vertical height from `1080` to `5176 px` (`ceil(5176 / 16) = 324` macroblock rows, matching `slice below image (640 >= 324)` verbatim) and exceeded Intel HD 530 VAAPI's `4096 px` maximum hardware surface height.

### 4.2 Two Compounding Code Gaps Found in `04c4fe2`
1. **Silent `0xB3` Skip on Broadcasts Carrying Quantiser Matrices (`FreezeFramePacer.scala:329`)**:
   - `parseMpeg2SequenceHeader` captured all 22 bytes (`0xB3` + `0xB5 1x`) and cleared `combined(11) & 0xFC` so synthesized packets had no trailing matrix bytes.
   - `sanitizeMpeg2Payload` guarded `0xB3` restoration with `(locked.length == 12 || (arr(i + 11) & 0x03) == (locked(11) & 0x03))`. Because `CBS 4.1` carries a 64-byte custom intra quantiser matrix (`arr(i + 11) & 0x02 == 0x02`), `(0x02 == 0x00)` evaluated to **`false`** on every keyframe — silently bypassing `0xB3` restoration.
   - The `0xB3` advance stride also ignored `load_non_intra_quantiser_matrix` (`76` vs. `140` bytes).
2. **Unsanitized & Unvalidated `0xB5 1x` (`Sequence Extension`)**:
   - `sanitizeMpeg2Payload` had **no `code == 0xB5` branch**, passing corrupted `progressive_sequence`, `chroma_format`, and `horizontal/vertical_size_extension` straight to FFmpeg/VAAPI.
   - `parseMpeg2SequenceHeader` did not validate `chroma_format == 4:2:0`, `horizontal/vertical_size_extension == 0`, or `marker_bit == 1`, and `MpegTsSync.cacheFlow` only compared `c.take(7) == hdr.take(7)` (`0xB3` dims) without confirming `0xB5 1x` bytes `12..21` or upgrading a 12-byte lock when `0xB5` arrived later or in a continuation packet.

## 5. Resolution & Verification

1. **[`4c36514`](file:///home/bdina/git/tablo2hdhomerun) — Quantiser-Safe `0xB3` Restoration & Exact Matrix Skipping**:
   - Restores `0xB3` bytes `0..10` and byte `11` bits `7..2` regardless of whether the live broadcast carries an intra, non-intra, or dual quantiser matrix (`12`/`76`/`140`-byte exact stride), while clearing corrupted low bits if `00 00 01 B5 1x` sits directly at `i + 12`.
   - Adds zero-allocation `MpegTsTypes.Mpeg2SanitizeResult` (`opaque type = Long`) separating `clampedSlices` from `restoredHeaders`.
2. **[`9a2e143`](file:///home/bdina/git/tablo2hdhomerun) — `0xB5 1x` Validation, Confirmation/Upgrade Locking, Sanitization & Anomaly Logging**:
   - Validates `Sequence Extension` headers (`chroma_format == 4:2:0`, `horizontal/vertical_size_extension == 0`, `marker_bit == 1`) before accepting them into `SeqHeaderLockState` (2-packet confirmation of both `0xB3` dims and 10-byte `0xB5 1x`, supporting automatic 12-byte → 22-byte upgrades including split `PUSI=1`/`PUSI=0` packets).
   - Restores corrupted 10-byte `00 00 01 B5 1x` headers in-stream (including bit-flips in the `0x1x` identifier nibble immediately following `0xB3`) while leaving `picture_coding_extension` (`0xB5 8x`), `sequence_display_extension` (`0xB5 2x`), and closed captions (`0xB2`) completely untouched.
   - Reports header repairs as `restoredSeqHeaders` in the 30s `[mpegts] transport anomalies` `WARN` log and logs initial lock / 22-byte upgrade at `INFO`.
   - Verified with 8 new unit & `MpegTsSync.cacheFlow` integration tests simulating the exact `08:14:09` `CBS 4.1` bit-flip (`439/439` tests passing under `-Werror`).
3. **Operational Plex Tuning Note (Non-Code)**:
   - Setting Plex **Transcoder quality** from `3` (*"Make my CPU hurt"*) to `0` (*"Automatic"*) in Plex Settings → Transcoder reduces CPU impact substantially if a software fallback ever occurs for an unrelated reason.
